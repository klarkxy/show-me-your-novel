# 开局四段协议（novel-benchmark.v3）

作者群的批评成立：V2.1 让每个模型自己起书名、起世界、起人物、起大纲再写五万字，公开雷达测到的主要是「总质量晕轮」，不是文风。文风只有在**世界、人物、章纲被冻成同一份提示词**之后才比得了。

本协议把工作拆成 grill-your-novel 里已经分开的层：规划归规划，正文归正文。规划层回答「发生什么」；正文层只回答「读起来怎样自然发生」。

## 分层锁定，不许一次写完

```text
1. 各模型只看题目，写世界
   → 人挑一套世界，锁住
2. 各模型看着已定世界写人物
   → 人挑一套人物，锁住
3. 各模型看着已定世界+人物写章纲
   → 人挑一套章纲，锁住
4. 冻成同一份开局提示词，各模型写正文
```

上一层没锁，下一层不准开跑。人物必须看见已定世界；章纲必须看见已定世界和已定人物。不要让模型在没见过世界的情况下凭空写人和章纲。

冻结后禁止再改世界/人物/章纲。正文模型不得补设定。

## A. 设计段

共享种子只有题目。具体世界观、谁出场、章怎么走，由模型自己定，提示词不预写答案。

交接仍用 JSON，方便下一层接着用：人物卡约束选择，不写属性表；章纲是交给正文的决策边界，不是正文缩写。

### 1. 世界设计

只看题目。评：这套世界是否撑得住这道开局题，规则和机构是否自己说得通。

### 2. 人物设计

只看题目 + 已定世界。评：这些人是否能在这个世界里做选择。

### 3. 大纲 / 章纲

只看题目 + 已定世界 + 已定人物。评：开局场面是否讲清，第一次不可逆选择是否落地，交接卡是否能交给正文。

## B. 正文段（同一提示词）

冻结包只含：世界、人物、章纲、以及协议写死的**短正向文风义务**（叙述经过视角、动作/对白/物件接力、关键处展开流程处压缩）。不把禁词表、审查清单塞进初稿。

每个模型：

- 按章纲的节拍逐节写，每节 500–1000 个可计字符；短了只追加一次隔离扩写，不拿同一份短稿空转重试；
- 下一节只看见世界、人物、**本节**章纲、上一节末约 400 字和本节任务；整份章纲和后面的节拍不进提示词；
- 程序按章拼接，**不再让模型重写整章**（避免统一成一种正确腔）；
- 每章 3–4 节，目标 2000–3000 字；全书 5–10 章。

完成线：读者能用自己的话复述初始事件，并指出第一次不可逆选择。这是开局标准，不是五万字长篇完成线。

正文只评文风与场景执行（自然度、声音、节拍承接、有没有把交接卡念出来）。不再用「题材兑现 / 时代质感」去给已经冻结的设定打第二遍分。

## 命令

```bash
# 默认只跑世界
python novel.py generate-v3 --all --exclude claude-

# 世界锁定后再跑人物
python novel.py generate-v3 --all --exclude claude- --stop-after characters --from-world minimax-m3

# 人物锁定后再跑章纲
python novel.py generate-v3 --all --exclude claude- --stop-after outline \
  --from-world minimax-m3 --from-characters kimi-k3

# 三件齐了再冻
python novel.py assemble-v3 --world glm-5.3 --characters kimi-k3 --outline gpt-5.6-sol

# 所有模型用同一冻结包写正文
python novel.py generate-v3 --model glm-5.3 --phase prose
```

## 评分

设计段和正文段分开评。不要拿 V2.1 的「题材兑现 / 时代质感」去给已经冻结的设定打第二遍分。

```bash
# 各模型自己交的世界 / 人物 / 章纲
python novel.py score-design --all

# 同一冻结包下的开局正文，只评文风与场景
python novel.py score-prose --all
```

V3 评委是 Sol、Grok、K3、DeepSeek V4 Pro、GLM 5.3。不占用 V2.1 冻死的 Opus 席。

冻结包已经由人合成。`score-design --assemble` 不再改冻。`_locked` 不是候选模型。
